PHP2Shell: two critical PHP RCEs, patch due today at 14:00 UTC
PHP is releasing fixes for CVE-2026-109618 and CVE-2026-109619 (both CVSS v4.0 9.2, unauthenticated remote code execution) today, Oct 21, at 14:00 UTC. That looks to have been moved up from Thursday.
Only PHP 8.2 and newer get a fix. 8.1 and older are end of life.
Affected versions aren’t confirmed yet. Reports say PHP 5 and later; Sansec says 5.4 and later.
No source says which server setups are affected, so assume all of them: PHP-FPM, Apache mod_php, CGI and FrankenPHP.
Exploitation is disputed.
Cloudflare’s CTO reported early attacks at 07:43 UTC.
Hadrian says it’s being exploited at scale.
Germany’s BSI says no attack is confirmed yet.
None of them has published evidence.
Sansec expects mass attacks within 15 minutes of the release.
The public write-up is not the real bug. The jackalsyn (J4ck3LSyN) write-up Beaumont shared has corrected itself.
Its original use-after-free path is now marked “DEAD”: a reference-count bump at session.c:3213 (Z_TRY_ADDREF) keeps the array alive, so it never gets freed.
What’s left is a smaller memory bug the author rates CVSS 5.3. It doesn’t run code and only works on Apache prefork with mod_php.
Geniar says that’s very likely not one of the embargoed 9.2 bugs, and not to treat PHP-FPM as safe because of it.
HN commenters also say the shared PoC doesn’t work.
The jackalsyn page links a downloadable exploit framework zip. Nobody should pull or run it.
RHEL heads-up. Remi’s repository (rpms.remirepo.net, common on RHEL) will not ship the fix today.
The PHP Foundation says to move to your distribution’s PHP packages or build from source now, so the fix can go in as soon as it’s out.
Distro packages often get backported fixes without the upstream version number changing. Check the package version or the Red Hat advisory, not php -v.
After patching, restart FPM, Apache and any long-running PHP workers. Running processes keep the old code in memory until they restart.
